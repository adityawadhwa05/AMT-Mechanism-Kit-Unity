# Project status — real CAD parts and full training UI

_Last updated 28 October 2026 · branch `feature/real-cad-parts-and-ui` · Unity 6000.0.60f1_

## Summary

The app has been rebuilt around the **real supplied CAD geometry**. The single-mesh GLB was split
into 37 named parts, out of 276 CAD bodies. The primitive-box reconstruction
(`NamedMechanism`, `IndexingDemo`, `IllustrativeMotion`) and the old UI (`TrainingUI`) were
removed; they remain in git history. All seven modules are implemented and share one code path
between the 3D viewer and AR.

## Architecture

- **Scenes:** `Assets/Scenes/Viewer.unity` → `AMT.AR.Core.ViewerBootstrap`; `Assets/Scenes/AR.unity` → `AMT.AR.AR.ARBootstrap`.
  The script GUIDs are unchanged so the scene files still bind.
- **Session:** `TrainingSession` owns `KitDatabase`, `KitModel`, `GestureInput`, `ExplodedView`,
  `MechanismCycle`, `GuidePlayer` and `ToolShowcase`. Only one system moves parts at a time, and
  `StopAll()` restores the rest pose.
- **View abstraction:** `IViewController` (camera, focus, reset, kit scale) is implemented by
  `ViewerBootstrap` (orbit camera) and `ARBootstrap` (placed kit).
- **UI:** `TrainingShell` holds the regions; one `ModuleScreen` subclass per module under `Assets/Scripts/UI/Screens/`.
- **Data:** `Assets/Resources/Data/components.json`, `tools.json`, `guide.json`.
- **Model:** `Assets/StreamingAssets/Model/MechanismKit_Parts.glb`, generated by `Tools/ModelPipeline` from the unchanged `MechanismKit.glb`.
- **Shaders:** `Assets/Resources/Shaders/` — `AMT/KitSurface` (lit + rim + highlight),
  `AMT/Ghost`, `AMT/Unlit`, `AMT/Ground` (shadow-receiving floor / AR shadow catcher), `AMT/ARPlane`.

## Fixed after the first Unity run

- The parts GLB had no default scene, so glTFast instantiated nothing. Fixed in `build_parts.mjs` and the GLB regenerated.
- The EventSystem is now kept across scene loads, avoiding an Input System UI module error on re-creation.
- Layout: the details-card title gap, home framing, control bar/caption centred between panels, exploded-view framing, minimum focus radius.
- Android: target API pinned to 36; ARCore and depth set to optional.

## Known risks / limitations

- **Untested at runtime.** Layout values (panel widths 420/470 px at a 1920×1080 reference) may need
  tuning on narrow 18:9–21:9 phones.
- **glTFast hierarchy assumption:** `KitModel` finds parts by GameObject name. Missing names are logged as warnings.
- **Mesh colliders** on 197k triangles are cooked at load. Measure the load time on mid-range phones;
  switch to `BoxCollider`s per part if it is slow.
- **Shadows** use the built-in pipeline's directional shadows. Mobile quality settings may need
  tuning (`QualitySettings` is set in the bootstraps).
- **Content limits:** roles marked `geometry` are unconfirmed. The assembly order is authored, not
  the manufacturer's. The station animation timing, solenoid stroke and inspection result are
  illustrative. Tool sizes and torques are unknown.
